01 / Why AXI

A small contract for a large API.

The CLI is shaped for automation first: explicit inputs, stable output classes, bounded reads, and no hidden state. Use the modeled surface for routine work; use GraphQL directly when the model needs more control.

01 / boundary

Non-interactive by construction

Commands never prompt. Supply identifiers, values, files, stdin, flags, or environment variables—so an agent can reason about the entire request before it runs.

02 / format

TOON first, compact JSON optional

Compact TOON is default. --format json emits compact JSON for API-backed results and post-parse application errors; parser-level and documented text exceptions remain.

03 / failure

Errors are data

Application errors carry stable type, code, and message fields. Exit 1 means operational failure; exit 2 means fix the invocation.

04 / payload

Compact projections

Use --fields compact on supported issue, comment, relation, and project reads. Connections retain pageInfo, so bounded output still says whether more exists.

05 / surface

Resource-shaped commands

Issues, teams, users, projects, cycles, milestones, initiatives, labels, documents, updates, comments, links, attachments, and relations share one discoverable command grammar.

06 / escape hatch

Raw GraphQL, still bounded

api accepts a query from an argument or stdin, with variables and pagination support. schema exports the current schema. Review raw mutations before sending them.

04 / Output contract

Make every result easy to branch on.

Success data and application errors go to stdout; diagnostics go to stderr. The same global flags work before or after subcommands, and --full opts out of the default string bound.

Invocation grammar
magi-linear-axi [--workspace <slug>] [--endpoint <url>] [--format toon|json] [--full] <command> [args]
TOON
Compact structured output is the default.
JSON
Use --format json for compact JSON consumers.
BOUND
Strings truncate at 240 Unicode code points unless --full is set.
Stable error shape
{"error":{"type":"auth","code":1,"message":"LINEAR_API_KEY must be set and non-empty"}}
Exit 0: success, empty result, or safe no-op. Exit 1: auth, config, network, API, or output failure. Exit 2: command or argument usage failure.

Parser nuance worth knowing

API-backed results and post-parse application errors can render as compact JSON. Help, version, completions, and a few documented single-document outputs remain plain text; parser-level failures happen before format resolution and are emitted as structured TOON.

What “read-only” means here

The harness used a least-privilege read-only key, query-only snapshot preparation, an AXI key-free wrapper and broker with bounded read validation, and the official MCP readonly endpoint. Mutation-shaped calls and shell composition were audited as safety/policy findings. The published comparison is aggregate-only.

Canonical answer schema: tested, not adopted

The final assessment retained the compact contract and rejected the experimental canonical answer schema, even though terminal answers were about 23% shorter. Across the aggregate comparison, output tokens rose +82%, cost rose +54.1%, and turns rose +41.2%. Canonical was a benchmark answer-format experiment, not a CLI output mode.
